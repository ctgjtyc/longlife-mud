## 二、整体架构：一个引擎承载全部诉求

- **状态即世界** → 世界状态机 + 因果标记 flags + 世界时间线。逻辑性（状态一致/剧情因果/世界自洽）自动成立。
- **事件即内容** → 数据驱动事件表 + 条件表达式。剧情深度（任务链/伏笔/多结局）变成数据；AI 动态生成 / 外部模组 = 往内容层灌数据。
- **数值即系统** → 六属性 + 境界 + 功法 + 背包 + 势力。玩法多样性在此展开，数值全部走配置表。
- **接口即扩展** → 存档版本化（多周目）、AI Provider 插槽（Ollama）、模组加载器（外部 JSON）、构建产物单文件化。

```
┌─ UI 层      渲染 / 按钮 / 战斗界面（独立）
├─ 引擎层      世界状态机 / 事件引擎 / 条件表达式 / 战斗 / 时间流逝 / 存档  ← 纯逻辑，可测试
├─ 内容层      事件表 / 装备 / 功法 / 任务链 / 成就 / 结局 / NPC / 势力 / 地图（JSON 数据）
├─ 模组层      外部 JSON 导入导出 / 模组包加载 / 内容校验（与 AI 生成共用管线）
└─ 接口层      存档版本化 / 多周目 / AI Provider / 平台壳（构建产物）
```

## 三、关键机制设计

### 3.1 世界状态机

```
gameState = {
  version,           // 存档版本（v2）
  year, cult, stone, hp, hpmax, status, equip, equipBonus,
  attrs: {体魄, 神魂, 灵力, 悟性, 道心, 魔性},   // 六属性（R6 用户设计）
  flags: {},          // 因果标记（核心）
  inventory: [],      // 背包（P3）
  reputation: {},     // 势力声望（P3）
  relations: {},      // NPC 好感度（P4）
  statuses: [],       // 持续 BUFF/DEBUFF（P3）
}
```

境界为**派生值**（由 cult 经阈值表计算，不落存档）：炼气→筑基→金丹→元婴→化神→渡劫→大乘。

### 3.2 条件表达式系统（方向⑤，P2 落地）

```
conditions: [ {type:"attr", key:"cult", op:">", val:500},   // 修为
              {type:"attr", key:"demon", op:">=", val:30},  // 六属性之一
              {type:"flag", key:"modao", val:true},
              {type:"year", op:">=", val:200},
              {type:"item", key:"续命丹", count:1},          // P3 接入
              {type:"rep",  key:"青云宗", op:">=", val:50} ] // P3 接入
```

- 数组 = AND；运算：`> >= < <= == !=`；单条不匹配即 false。
- P2 落地 attr/flag/year 三类，item/rep 预留接口。

### 3.3 六属性体系（用户设计，替代原四维方案）

| 属性 | 作用 |
|------|------|
| 体魄 | 战斗血量/近战，攻击加成 |
| 神魂 | 法术强度/神识抗性（抗夺舍/心魔） |
| 灵力 | 技能消耗池/法术威力（P3 技能系统接入） |
| 悟性 | 修炼速度（cult 年增长） |
| 道心 ↔ 魔性 | 对立双属性：入魔 +魔性，正道 +道心；道心高解锁正道选项，魔性高解锁魔道路线 |

- 修炼公式：`gain = n × (2 + (悟性-10)×0.1 + 装备×0.15)`，悟性 10 时与原版完全一致（旧档迁移后数值不漂移）。
- 战斗接入：攻击 `15 + 装备×1.2 + cult×0.04 + 体魄×0.5`（P2 起生效，平衡归 balance.js 管）。

### 3.4 读档 bug 修正方案（P1 发现，P2 修复）

根因：`loadGame → routeByStep` 直接重放 step 函数，而 step 函数开头带副作用（passYear/log/成就）。

修正（状态机思维）：**进入（enter，带推进副作用）与场景渲染（scene，幂等）分离**：

- `enterHide()`：passYear(30)+log 时光流逝 → `sceneHide()` 渲染选项
- `sceneHide()`：纯渲染（log 标题 + 按钮），无副作用
- `routeByStep()` 读档只调 scene 版 → 读档不再推进时间
- 剧情内按钮（「继续隐居 70 年」等）语义不变（按钮点击 = 推进事件）
- 副本场景（stepCopy*）本就无副作用，不拆

### 3.5 存档 v2

- `version:2` + `migrateSave()` 迁移链：v1（无 version/attrs/flags）→ 补默认六属性与空 flags，数值零漂移（悟性默认 10 保持 cult 公式与原版一致）。
- 多周目继承（P5）。

### 3.6 世界时间线 / 模组系统 / NPC 对话树 / AI Provider

见 v0.2 3.2/3.6/3.7/3.5 节，不变（落位见第四节扩展全景）。
