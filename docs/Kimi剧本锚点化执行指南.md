## 二、最省 Token 执行策略（核心，务必遵守）

### 策略 1：按卷开会话，一卷只读一次文件（6 次会话，文件只读 6 次）

| 会话 | 源文件（直接读取，勿复制文本进对话） | 处理段 |
|------|-----------------------------------|--------|
| 1 | 系统赋我长生，活着终会无敌(1-500章).txt | ch1-200 / 201-400 / 401-500 |
| 2 | (501-1000章).txt | ch501-700 / 701-900 / 901-1000 |
| 3 | (1001-1500章).txt | ch1001-1200 / 1201-1400 / 1401-1500 |
| 4 | (1501-2000章).txt | ch1501-1700 / 1701-1900 / 1901-2000 |
| 5 | (2001-2500章).txt | ch2001-2200 / 2201-2400 / 2401-2500 |
| 6 | (2501-2712章).txt | ch2501-2712（注意：该卷实际从 2499 章起，2499-2500 归入本段） |

**为什么省**：Kimi 长上下文内文件读一次即驻留，同一会话内连续产出 3 段，不需要在提示词里搬运任何原文——比「每段单独粘贴原文」节省约 90% 输入 Token。

### 策略 2：跨段衔接用「接力摘要」，不回读前文

每段输出末尾附 ≤200 字的【接力摘要】（当前进度境界 + 活跃人物状态 + 未回收伏笔清单），下一段直接引用它，**不要回头重读已总结的章节**。

### 策略 3：输出零废话

- 不要开场白、不要解释、不要「好的，以下是…」，直接输出结构化内容
- 每章事件**一行一条**，不展开描写
- 不引用原文大段文字，只提炼事实

### 策略 4：失败重试只补缺段

某段输出中断/不满意时，只要求重出该段（说明段号），不要整卷重来。

## 三、每段固定输出格式（严格按此，程序要解析）

```
【段 ch{起}-{止}】

## 事件链（每章一行：章号|事件|触发条件或前置）
1|陈浔获得长生系统开始加点|穿越开局
2|…

## 境界进度（仅发生变化的章）
章号|角色|变化（如：炼气三层→炼气五层）

## 人物（本段新出场或关系变化）
章号|人物|身份/与主角关系|备注

## 伏笔登记
[埋] 章号|伏笔内容
[收] 章号|回收内容|对应埋设章（不知则写「待考」）

## 接力摘要（≤200字）
当前境界/主线状态/活跃人物/未回收伏笔要点
```

## 四、质量红线

1. **忠实原文**：事件/人物/境界必须出自原文，不确定就写「待考」，禁止编造
2. **章号准确**：以原文「第N章」标记为准（卷区间文件名仅参考，已证实 2501-2712 卷实从 2499 章起）
3. **缺章跳过**：2663/2667 章源文缺失，事件链中直接跳过不占位
4. **伏笔宁缺毋滥**：只登记明确的埋设/回收，猜测性关联标注「待考」

## 五、产物去向（用户操作，Kimi 无需执行）

每段输出请用户保存为单独文本（文件名建议 `kimi-ch{起}-{止}.txt`），交回 Qoder CN 后由脚本自动合并进：
- `story-lib/scenarios/xiuxian/chapters/digest-{起}-{止}.md`（56 份摘要槽按段对应）
- `story-lib/scenarios/xiuxian/anchors.json`（事件链→锚点：chapter/keywords/trigger/summary）
