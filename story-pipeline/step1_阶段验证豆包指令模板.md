  ```bash
  py -3 stage_probe.py --list
  ```
  预期看到 S1~S15 共 15 行，边界与下表一致。若报错，先修工具再继续。

## 一、首次会话：给豆包建任务框架（一次性，约 2 分钟）

> 目的：让豆包锁定「审校员」角色、明确份内/份外、写下输出格式。只在**新对话**做一次，后续轮次复用。

**第 1 步**：新开豆包对话。

**第 2 步**：把下方命令的输出**原样粘贴**进豆包（15 阶段表，让豆包有全局边界）：
  ```bash
  py -3 stage_probe.py --list
  ```

**第 3 步**：回车后，把「第四节·固定指令(首次框架版)」整段粘贴进豆包，替换三处占位为**第一轮考察的阶段**：
- `{阶段id}` → 如 `S1`
- `{章范围}` → 如 `1-33`
- `{用户说法}` → 把用户这一轮的原话贴进去

**第 4 步**：检查豆包回复是否带出「结论/证据/理由」三段标题。若豆包只回客套或跑题，把「第四节·固定指令」再贴一次，并加一句「严格按上述输出格式作答，不要写任何无关内容」。

> 至此任务框架建立。之后每轮只做「第二节」的 5 步，不再重复本节。

---

## 二、每轮验证（用户给一个新说法时，约 3-5 分钟）

> 目标：拿豆包的阶段边界 + 用户说法，用原文核验，产出「成立/证伪 + 章号证据」。

**第 1 步 · 定位章范围**
- 用户说法通常提到阶段或具体情节。若提到阶段（如「S1 出山」）：查第四节阶段表，得到章范围。
- 若用户只给情节不给章号：先用 `stage_probe.py --list` 看哪个阶段名最贴近，再取该阶段范围。
- 决定要取几章：为快速验证，取**说法涉及的核心几章**（通常 2-5 章），不必整段。

**第 2 步 · 取原文**
- 按阶段取章（推荐）：
  ```bash
  cd D:\AI-app\longlife-mud\story-pipeline
  py -3 stage_probe.py S1 5-6
  ```
- 或跳过阶段直接按章号区间取（跨段/补验）：
  ```bash
  py -3 stage_probe.py --range 2672-2674
  ```
- 预期输出：每章以 `【第N章 标题】` 开头，正文 + 血缘头。若某章显示 `[源文缺失]`，属正常（缺口 2664-2669、2674-2973），照常作为占位喂豆包。

**第 3 步 · 组装指令**
- 复制「第五节·固定指令(每轮版)」。
- 替换三处占位：`{阶段id}`、`{章范围}`、`{用户说法}`。
- 若上一轮豆包还在同一会话，且已建框架，可省略背景段，只发「第五节」核心段。

**第 4 步 · 发豆包**
- 在豆包对话中，先贴「第 2 步」取得的原文全文，回车，再贴组装好的指令。
- 顺序必须是「原文在前、指令在后」，让豆包先读数据再读目标。

**第 5 步 · 收豆包结论并反查**
- 豆包应回三行：`结论 / 证据 / 理由`。
- 若豆包给「证伪 / 部分成立」：要求它补「具体到章」的反证，否则不予采纳。
- 拿豆包给的章号回工具反查原文，确认它没编造（对齐 EP0-6 / 事实核验）：
  ```bash
  py -3 stage_probe.py S1 7
  py -3 stage_probe.py --range 4-8
  ```
- 记录结论到轮次记录（见第六节）。

## 三、边界复核（豆包声称「边界应调整」时，约 3 分钟）

> 触发：豆包在结论里顺带指出相邻阶段边界不贴合转折点。

**第 1 步**：让豆包给出建议的新边界章号（如「S1 应到 ch31」）。
**第 2 步**：取拐点章原文验证转折是否真实（看地图/境界/大事件切换）：
  ```bash
  py -3 stage_probe.py --range N-1 N+1
  ```
  （N 为建议边界章号，前后各多看 1 章）
**第 3 步**：若原文确实在 N 处转折，才改 `stages.json` 对应 stage 的 `range`；若证据不足，维持原边界并让豆包再给证据。
**第 4 步**：改完 stages.json 后，重跑 `py -3 stage_probe.py --list` 确认边界被正确读取，且无章号重叠/断档。

> 边界是草案，样品测试阶段允许反复调；改 stages.json 即可，脚本不用动。

## 四、固定指令（首次框架版）—— 仅新对话用

```
你是《系统赋我长生》原著剧情阶段规划审校员，配合我完成「阶段划分样品测试」。

【本阶段】{阶段id}（第 {章范围} 章）
【用户说法】{用户对该阶段的说法，原样粘贴}

背景：已有一份阶段划分草案（stages.json，15 个语义阶段），章节原文由 stage_probe.py 按需提供给你。相邻阶段边界基于标题+关键词标定，尚未精修，你的复核结果将用于修正边界。

你的任务仅在以下范围内，禁止越界：
1. 我给出「某阶段 / 某几章」的说法时，基于我提供的原文逐条判断【成立 / 证伪 / 部分成立】，并给出章号证据。
2. 复核相邻阶段边界是否真的贴合叙事转折点（地图 / 境界 / 大事件切换处）；若不准，指出应调整到哪一章。
3. 阶段结束只作为后续阶段的伏笔源，不独立成可玩主线。
4. 源文确有缺失章节（2664-2669、2674-2973），我提供的原文若为占位「[源文缺失]」，你不要脑补内容，直接据实说明。

我已经把相关章节原文贴在上方。请基于原文作答。

输出严格按以下格式，禁止开场白 / 解释 / 客套 / 评价文笔：

结论：成立 / 证伪 / 部分成立
证据：第 N 章（原文该章命中句子的摘录）
理由：≤50 字
```

> 每轮验证后，把结论记到 `story-pipeline/阶段验证记录.md`（可手动追加），格式：

```
## {日期} 轮次 {n}
- 用户说法：...
- 阶段：S1 (1-33)
- 取章：ch5-6
- 豆包结论：成立
- 证据章号：ch5（出山段：...）、ch6（入磐宁城：...）
- 反查结果：与原文一致
- 边界调整：无 / S1 建议调到 ch31（待复核）
```

> 理由：豆包结论是「待核验线索」，落盘留痕（对齐 C-5），后续迭代阶段边界时有据可查。
