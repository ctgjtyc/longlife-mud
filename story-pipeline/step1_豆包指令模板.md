# Step 1 豆包 2.1 turbo 槽位消化指令模板 v1

> 管线：J35《系统赋我长生》剧本锚点化 | 上游：Step 0（chunks/ 已就绪）| 下游：Step 2 机器校验
> 用法：本文件是**指令模板**，不是一次性提示词——每槽复制「固定指令」段，替换槽位占位与接力摘要即可。

## 一、每槽操作流程（3 步）

1. **取上槽接力摘要**：打开 `story-pipeline/state.json`（或上槽产物「## 接力」节），把 ≤200 字接力摘要贴入指令
2. **喂本槽原文**：把 `chunks/chXXXX-YYYY.txt` 全文粘入豆包对话（若豆包支持跨请求上下文复用，可同会话内按章分批上传）
3. **发固定指令**：粘贴下方「固定指令」，替换 `{槽位}` `{章范围}` `{接力摘要}` 三处占位

## 二、跨请求上下文复用（双模判断）

- **自动继承可用**：同一会话连续上传分片后模型自动继承前文 → 接力摘要段可省略，指令里填「继承」
- **无此功能/不确定**：必须走接力摘要模式（固定指令自带接力摘要段），防伏笔断链
- **判断方法**：第 1 槽完成后，检查输出是否引用了第 1-49 章内容；若每批只回最后几章 = 未继承，下一槽切回接力摘要模式

## 三、固定指令（每槽复制，替换占位）

```
你是《系统赋我长生》原著情节锚点化处理器。任务：把本槽原文压缩为结构化锚点数据，供游戏剧情引擎引用。

【本槽】{槽位}（第 {起} - {止} 章）
【上槽接力摘要】{接力摘要}

输出严格按以下五节，禁止开场白/解释/客套：

## 事件链
格式：`章号|事件概括|触发物/条件`
- 每章 1-2 行，只记影响后续的事件（战斗/突破/收徒/获得物品/重要对话/地点转移）
- 事件概括 ≤25 字；触发物 = 该事件由什么触发（物品/人物/境界/无）
- 例：`12|陈浔濒死觉醒系统面板，绑定宿主|生死危机`

## 境界
格式：`章号|人物|境界→新境界`（仅记录本槽内的境界变化）

## 人物
格式：`章号|人物|身份/当前状态`（仅新出场或状态重大变化者）

## 伏笔
格式：`[埋]章号|伏笔内容` 或 `[收]章号|回收内容|埋设章号`
- 埋：作者明确留下但未解释的线索（神秘人物/异常物品/未解之言）
- 收：前文伏笔在本槽兑现，必须标注埋设章号；不确定标 `[收]章号|...|待考`
- 宁缺毋滥：拿不准的不是伏笔，不写

## 接力
≤200 字：当前境界格局 / 活跃人物名单 / 未回收伏笔清单（编号引用），供下一槽继承
```

## 四、质量红线

1. **忠实原文**：不脑补、不评价文笔、不写「本章主要讲述了」
2. **章号以正文为准**：正文没有的章跳过（末卷章号跳变：2664-2669 与 2674-2973 缺章，源文如此非管线错误）
3. **缺章跳过**：不要编造
4. **伏笔宁缺毋滥**：拿不准标「待考」兜底
5. **产物落盘**：每槽输出存为 `story-lib/scenarios/xiuxian/chapters/digest-{起}-{止}.md`（文件名以 manifest.json 的 digest 字段为准）

## 五、槽位速查

- 55 槽：前 53 槽各 50 章 + 残卷 2 槽（ch2651-2673 共 17 章、ch2974-3010 共 37 章），文件 `chunks/ch0001-0050.txt` … `ch2974-3010.txt`
- 槽位完整清单、每槽字符数、digest 目标路径：见 `story-pipeline/manifest.json`（Step 0 生成）
- 进度与断点：`progress.json`（done/redo）与 `state.json`（接力状态）
